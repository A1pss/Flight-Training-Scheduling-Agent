# FTS 飞行训练排班系统 · 用户手册

**面向** 排班员 · 训练主任 · 查看者 · **版本** v1.0.0

---

## 0. 这个系统是怎么工作的（一分钟）

**排班结果由求解器算出来，不是模型写出来的。**

```
你说的话 ──▶ 翻译成精确的求解输入 ──▶ CP-SAT 求解 ──▶ 14 条规则独立复核 ──▶ 给你看
             （模型做这一步）           （确定性）      （另一套独立实现）
```

模型只做三件事：**把人话翻译成求解输入**、**冲突时组织你能懂的权衡**、
**对结果给出解释**。它**不生成、不修改、不参与任何一条架次记录**。

这带来两个你能直接依赖的性质：

- **同样的输入永远给同样的结果**。今天排的和明天重排的，只要数据没变就逐字节相同。
- **排出来的班 100% 合规**。不是「尽量合规」——求解器产出的每个方案都由一套
  **完全独立实现**的校验器逐条复核过，两边判定不一致时系统**不出结果**而是报警。

## 1. 四个页签

| 页签 | 看什么 |
|---|---|
| **排班结果** | 三张表（按人 / 按机 / 按日）+ Sheet 4 七个区块 + 周甘特图 |
| **约束校验** | 14 条规则逐条的检查结果与「已检查 N 项」 |
| **运作过程** | 这次排班经过了哪些节点、每步用了多久、有没有重解 |
| **解释报告** | 为什么这么排；每句话都能追到具体的架次 |

顶栏常驻四样：**快照 id** · **规则版本** · **语义版本** · **● 离线运行**。
换了数据或改了规则，这几个串会变 —— 它们决定了结果，所以永远显示在最上面。

## 2. 排一次班

### 2.1 用自然语言

侧栏输入框直接说，例如：

- 「给下周排班」
- 「排 2026 年 1 月 5 日那一周」
- 「吴鹏周一请假，重排这一周」

系统会先**回显它的理解**（"我理解为：排 2026W02，吴鹏 01-05 不可用"），
你确认之后才真的去解。**翻译错了不会已经排了一版**。

### 2.2 用表单（LLM 不可用时）

侧栏「表单排班」展开，填排班周（**必须是周一**）即可。这条路径**一次 LLM 都不调**，
所以模型服务挂了、没有 GPU、网络怎样都不影响。

### 2.3 等结果

提交后立即拿到一个任务号，页面每 1.5 秒轮询一次，显示当前阶段与百分比：

```
解析意图 → 编译约束 → 求解 → 校验 → 生成报表 → 等待确认
```

一次基准规模的排班约 **20 秒**。停在 95% 的「等待确认」是正常的 ——
剩下 5% 要你按确认。

## 3. 看懂结果

### 3.1 四个指标

页面顶部四个数：**架次 / 带飞 / 单飞 / 阻塞项**。

**「阻塞项」不是错误。** 它是「这个人这门课这周排不了，原因是 XXX」的**显式披露**。
最常见的原因是**先修没完成**：B 类课目要求 A 类**全部**完成（A-1 且 A-2），
只飞过 A-1 的学员，B 类会被如实列为阻塞而不是硬排上去。

### 3.2 三种求解状态，含义完全不同

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| **OPTIMAL** | 找到最优解并**证明**了它最优 | 正常确认 |
| **FEASIBLE** | 找到可行解，但没来得及证明最优 | 可用，但换台机器重跑可能得到另一个同样合规的解 |
| **INFEASIBLE** | **证明了无解** | 看松弛提案（§5） |
| UNKNOWN | 超时，既没找到解也没证明无解 | **不等于无解**，延长时限再试 |

> **UNKNOWN 与 INFEASIBLE 是两回事。** 前者是「没算完」，后者是「算完了，确实排不出来」。
> 系统在数据、错误码、界面配色上全程把两者分开。

### 3.3 约束校验面板

14 条规则逐条列出，每条显示 **「已检查 N 项」** —— 那是真实的检查次数，
不是固定文案。点开可以看到**规则原文**与它在知识库里的出处。

**这一栏全绿是硬性的。** 求解器与校验器是两套独立实现的代码，任何一条不一致，
系统都不会把方案给你，而是报 `FTS-3003` 让人来查。

## 4. 多轮修订

看到结果不满意，直接说：

- 「把何超周三的课挪到周四」
- 「AC34 周五别用」
- 「张勇这周少排一次」

每一轮的流程是固定的**两次确认**：

```
你说的话 → 系统回显「我理解为…」→ 你确认 → 重解 → 给你新方案 → 你确认归档
```

**第一次确认是确认「翻译对不对」，第二次才是确认方案。** 这样翻译错了不会白排一版。

**撤销**：「撤销上一条」会把那条约束去掉**再解一次**。注意它不是「把旧方案取回来」
—— 重解出来的方案会尽量贴近**当前**这一版，可能与最初那版不完全相同，
但两者都是满足同一套约束的最优解。

## 5. 排不出来的时候

系统给出**最小冲突集**（是哪几条约束打架）+ **归因** + **松弛提案**：

| 档位 | 放宽什么 | 谁能批 |
|---|---|---|
| Tier 0 | 不放宽 | — |
| Tier 1 | 允许欠账并**显式披露** | 排班员 |
| Tier 2 | 「每周至少一次 A 类」降级为软目标 | 排班员 |
| Tier 3 | 更大幅度的放宽 | **训练主任** |

**永远不会自动放宽。** 每一档都要人点头，且**档位会写进产物**——
哪一版计划用了哪一档，翻归档就能查。

---

## 6. 确认与归档

「确认并归档」之后系统会在**一个事务里**做四件事：归档计划 · 推进训练进度 ·
结算欠账 · 写下次排班要用的频率锚点。

**这是全系统唯一不可撤销的写操作**，所以只有**训练主任**能做。

归档后可以下载 xlsx（四张工作表，格式与现行版式一致），
也可以在「历史计划」里按周查。

**驳回**不会自动重排 —— 驳回的理由要人来定。写清意见，再发起一轮修订。

## 7. 上传新数据

「数据摄取」页签：上传人员 / 飞机 / 课目 / 规则文件 → 看变更 Diff →
逐条裁决冲突 → 确认入库。

三条要知道的：

1. **抽取失败会阻断，不会「尽力而为」地入一半。** 宁可让你重传，也不让脏数据进库。
2. **同一份文件内部前后矛盾时系统会问你**（比如某人的资质到期日在总表和明细表里
   不一致），**不替你选**。
3. **少传一类数据会提示补传**，不会拿上一版数据顶替。缺课目文件的「课程开始日期」
   时会直接问你要一个日期 —— 系统**没有默认值**，因为那个日期填错要迁移整张表。

## 8. 常见问题

**Q：为什么某个学员这周一次都没排上？**
看阻塞项。多半是先修没完成（A 类要 A-1 和 A-2 都飞完才解锁 B 类），
或者他这周的可用时间与飞机/空域/教员排不到一起。

**Q：为什么同样的话排出来的班不一样？**
只要快照 id、规则版本、语义版本三个串一样，结果就一样。三者任一变了，
结果就可能变 —— 顶栏一直显示它们就是为了这个。

**Q：模型服务挂了还能排班吗？**
能。用侧栏的「表单排班」。排班链路一次都不经模型。

**Q：我是查看者，能下载 xlsx 吗？**
能，且拿到的文件与排班员拿到的**完全相同**。

**Q：两个人同时排同一周会怎样？**
后提交的会被立即拒绝，并告诉你「谁在排、还剩多久」。**不排队** ——
排队会让你以为提交成功了。换一周提交则互不影响。

**Q：解释报告里的话可信吗？**
解释文本只允许引用求解结果里真实存在的字段，逐句核验过；核验不过的句子会被
直接剔除。但它仍是模型生成的文字 —— **要作为依据的永远是「约束校验」页签**。
