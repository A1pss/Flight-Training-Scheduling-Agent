## ⚠️ 这份文件里没有任何修复规则，也不许往里加

**换行断词的修复正则在代码里**（`backend/ingestion/repair.py`），不在这份
markdown 里。这不是随手放的：修复层带后置断言，抽取失败宁可抛错阻断，
也不让脏 token 进库。把正则挪进 skill，等于让一份「业务方可编辑、改错了不会
有任何后果」的文件决定入库的数据长什么样——那条红线当场就破了。

隔离测试 S6 专门验这一条：**改这份文件里关于 `missionC1` 的说明，摄取结果
必须一个字节都不变。** 所以下面写的是「有这个现象、注意看」，不是「遇到它
该怎么改」。

## 表长什么样

`aircraft.pdf` 的「一、飞机资源明细」是一张宽表，一机一行：

| 机号 | 机型 | 座位 | 每日可用窗 | 周转(分) | 维护计划 | 适配课目 |

「适配课目」那一列最宽，PDF 排版会把它折成多行，于是同一架飞机的信息横跨
若干个文本行。抽取时要**先把属于同一机号的行聚起来**，再解析列。

## 已知的变体现象（只描述，不给修复方案）

**一、课目编号在换行处被折断。** 「适配课目」列里的 `missionC-1` 有可能在
PDF 里被折成 `mission` + `C-1` 两段，粘回来时中间的连字符也可能丢掉，
于是出现 **`missionC1`** 这种少了连字符的变体。看到它就知道这一行经历过
折行——**它是现象，不是合法编号**。合法编号一律是 `mission` + 大写字母 +
`-` + 数字。

**二、同类现象还会出现在别的列。** 机号 `AC10` 在极端排版下会被折成
`AC` + `10`；周转时间 `30` 与单位「分」之间可能插入换行。原则一样：
出现「看着像被切了一刀」的 token，就说明这一带经历过折行，要连上下文一起看。

**三、脏 token 不许猜着修。** 抽取阶段遇到不确定的值，**报出来阻断**，
不要按「大概是这个意思」填一个进去。

## 两处最容易抽错的事实

**AC73 是 JL-8，不是 JL-9。** 早期文档里把它标成 JL-9，与 `aircraft.pdf`
冲突，已按 PDF 更正。JL-9 只有 **AC84 与 AC95** 两架。

**JL-8 与 JL-9 的周转时间不同**：JL-8 是 30 分钟，JL-9 是 40 分钟。
这一列是**逐机一列的数据**，不是按机型推出来的常量——用户换一批数据时
它会跟着变，不要拿机型去反推。

## 维护计划列

「2026-01-09 全天定检」这种写法要拆成日期 + 时段。**「全天」不是一个时刻**，
它对应当日整个训练窗。写成 `00:00-23:59` 或 `06:00-18:00` 都可以由代码决定，
抽取只负责如实交出「这一天全天」这个事实。

## 机号与机型都不是枚举

生产形态是用户上传自己的机队文件。`AC` 前缀后的位数不固定，机型名由数据决定。
看到 `AC100` 或 `JL-10` 不要当成抽取错误。
