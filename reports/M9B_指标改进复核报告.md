### 1.2 指标算法更正

实验五原实现有两处会改变结论的口径问题：

- 可选步骤命中原先只进入工具选择分子、不进入分母，可能把工具选择准确率抬高，甚至出现
  `hits > required_steps`。现改为工具选择分子、分母都只统计必需步骤；可选步骤只进入参数诊断。
- 真·缺失调用率的分母原先包含合法零工具轨迹。现只统计 `required_steps > 0` 的轨迹，
  分子仍严格按 `observed_calls == 0`，即 Z-41 的“一个工具都没调”。

新增快照测试冻结实验一完成率/槽位 F1/误执行率和实验五工具选择/缺失调用/路径等分母。
按冻结后的口径回看 30 条查询轨迹，Z-44 前后的真实变化为：

| 版本 | 工具选择 | 真·缺失调用 | 路径正确 |
|---|---:|---:|---:|
| Z-44 前（`exp5_final_v2`） | 19/35 = **54.29%** | 5/30 = **16.67%** | 6/30 = 20.00% |
| Z-44 后（`exp5_z45`） | 18/35 = **51.43%** | 6/30 = **20.00%** | 6/30 = 20.00% |

因此原先看到的 65.71% → 60.00% 含有可选步骤抬分；回退方向存在，但绝对值不是
冻结后的工具选择口径。

完整性核对：每轮 360 条、三轮共 1080 条、错误 0；三轮的完成率、意图准确率和
误执行率逐轮完全相同。

| 指标 | Z-44 全量 | 本轮全量 | 变化 |
|---|---:|---:|---:|
| 任务完成率 | 83.61% | **82.22%** | -1.39 个点 |
| 意图准确率 | 91.11% | **91.11%** | 0 |
| 槽位 micro F1 | 84.78% | **87.72%** | +2.95 个点 |
| `constraint_modifiers` F1 | 10.26% | **51.35%** | +41.09 个点 |
| 误执行率（照报，不设门槛） | 7.78% | **10.00%** | +2.22 个点 |

`constraint_modifiers` 的本轮混淆量为 `tp=114 / fp=3 / fn=213`，即每轮
`38/1/71`。这证明 Z-45 的确定性扫描在全量上有效，但 20 条探针的 **3→18** 不能
外推成“全量大致同幅提升”：全量最终 F1 是 51.35%，仍有 213 个漏检。

在开跑前另做了方向性审计，发现三类会把用户意图翻成反方向求解输入的高风险误报：

- “别用 AC73”不能生成 `PIN_RESOURCE AC73`；
- “RWY-2 关闭”不能生成 `PIN_RUNWAY RWY-2`；
- “12:00 之后不飞”不能生成 `PIN_TIME not_before=12:00`。

修复后离线扫描为 `tp=35 / fp=1 / fn=74`。唯一剩余表面误报是“用 AC10 排班”，
但真实路由会先因缺周次反问，没有进入 Planner。扫描器仍采取保守原则：宁可把未覆盖表达
交给 Planner，也不生成方向相反的确定性修饰。

## 3. 实验五：回退定位

### 3.1 路由、会话、Knowledge 三分法

逐条比较 `exp5_final_v2` 与 `exp5_z45` 后，只有 `TRJ-KNW-019` 从工具路径变为
`route → END`。这说明该次回退首先是路由结果变化，不是整批共用状态造成的系统性退化。

| 候选原因 | 证据 | 判定 |
|---|---|---|
| 路由 | 查询被 `no_slots_at_all` / `week_missing` 这两个排班缺槽特征扣分；模型臆造的排班槽位还会制造假歧义 | **成立并已修** |
| 会话状态 | 批跑器一直是一条轨迹一个数据库会话；最终 record/replay 30 行逐字节一致 | **排除跨轨迹串扰** |
| Knowledge | `TRJ-KNW-028` 已进 Knowledge；改写层把同句“他”和 `JL-9` 误判成实体歧义，放行后模型又把机型塞进 `prereq_cte.mission_id` | **成立并已修** |

### 3.2 修复

- 查询路由只保留“确实出现在用户原文且已确定解析”的二级槽位；查询不再受排班专属的
  `no_slots_at_all` / `week_missing` 特征惩罚。
- Knowledge 改写只接受模型从原文逐字圈出的 surface；术语对齐先于实体消解；机型不再按
  单架飞机消解；同一句中的人称代词可承接唯一显式实体。
- Knowledge system prompt 升到 v2，明确 `prereq_cte` 只接收 `mission...` 课目编号，
  `JL-*` 是机型，身份/机型资质等结构化事实必须走 `sql_query`；参数 schema 同步声明边界。
