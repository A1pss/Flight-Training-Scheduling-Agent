## 3. 关键决策与理由（**踩过的坑都在这里**）

### 3.1 ⚠️ Ollama 版本钉在 v0.6.8，不要随手升级

**这是本窗口最大的坑。** 最初装的是最新版 v0.32.6，它启动正常、接口正常、`ollama run` 也能出中文——
但日志里藏着：

```
level=WARN source=cuda_compat.go msg="NVIDIA driver too old"
      device="NVIDIA GeForce RTX 4090 D" compute=8.9 driver=535 required_driver="550 or newer"
level=INFO msg="inference compute" id=cpu library=cpu ...
```

**它静默退化成了 CPU 推理。** 本机驱动是 535.230.02（CUDA 12.2），而 Ollama ≥ v0.30 的 CUDA 运行时是
**12.8**，直接判定驱动过旧。我用 `llama-server --list-devices` 单独验证过：CUDA 12.8 运行时在
535 驱动下 `Available devices: (none)`。

改用 **v0.6.8**（同时提供 cuda_v11(11.3) 与 cuda_v12(12.4) 两套运行时），启动日志变成：

```
level=INFO source=types.go:130 msg="inference compute" id=GPU-0a406c11-… library=cuda variant=v12
      compute=8.9 driver=12.2 name="NVIDIA GeForce RTX 4090 D" total="23.6 GiB" available="23.3 GiB"
```

**升级 Ollama 的前置条件是先把驱动升到 ≥550（需要 root）。** 理由已写进 `install_ollama.sh` 顶部注释。
旧版本保留在 `.tools/ollama-v0.32.6/`，需要时可对比。

### 3.2 ⚠️ HTTP 代理会损坏长连接的 TLS，服务端也会继承

本机 `HTTP(S)_PROXY=http://127.0.0.1:17890`。它在长连接上会损坏 TLS 记录：
curl 报 `decryption failed or bad record mac`，ollama 报 `tls: bad record MAC`。
表现是**大文件必然中断**——Ollama 拉 9GB 模型时每次只能进 60MB 就断，速率 ~43 MB/min。

**关键教训**：我一开始只在 CLI 侧 `env -u https_proxy` 绕过，没用——
**真正下载的是 ollama 服务端进程，它继承了启动时的环境变量**。
必须在 `start_ollama.sh` 里 unset，已修。修完后模型拉取速度恢复正常。

同样的处理已加进 `fetch_bge.sh`、`install_ollama.sh`。

### 3.3 PG/Redis 装在独立 conda 环境 `fts-svc`，不装进 `schedule`

`postgresql`/`redis-server` 会拖进 openssl/icu/krb5 等一堆 C 库，装进 `schedule` 有打断
已装好的 torch 2.8.0+cu126 / paddlepaddle 依赖的风险。`schedule` 保持纯 Python 环境。
脚本通过 `FTS_SVC_BIN` 引用二进制，对使用者透明。

**另外**：conda-forge 的 Redis 服务端包名是 `redis-server` 不是 `redis`（后者是 Python 客户端），
且默认解析到 **8.10**，必须显式 `redis-server=7` 才拿到 7.4.7。

### 3.4 `~/.condarc` 加了 `envs_dirs`

`schedule` 环境在 `/shares2/mingde/miniconda3/envs/`，但 PATH 上的 conda 是 `/home` 那个，
`conda run -n schedule` 直接报 `EnvironmentLocationNotFound`。
CLAUDE.md §2 硬性要求这条命令可用，故在 `~/.condarc` 顶部加了 `envs_dirs`。
**原文件备份在 `~/.condarc.bak.m0`。** 这是本窗口唯一改动的仓库外文件。

### 3.5 `transformers` 锁 4.x

FlagEmbedding 1.4.0 的 reranker 调用 `tokenizer.prepare_for_model`，该方法在 transformers 5.x 中已移除
（`AttributeError: XLMRobertaTokenizer has no attribute prepare_for_model`）。
已在 `requirements.in` 锁 `transformers>=4.44,<5`，实装 4.57.6。

### 3.6 三处对配置的「收紧」，不是放宽

`.importlinter` 有三处与 v6 附录 A 字面不同，**全部是更严的口径**，按 CLAUDE.md §6 在此单列：

1. **禁令二的 source 由 `backend.nodes.compile_spec` 改为整个 `backend.nodes` 包。**
   原因：`compile_spec.py` 由 M2 交付，现在不存在，import-linter 会报「模块不存在」而直接失败。
   改为整包更严，也更贴合铁律 4「六个确定性节点都不读 Skill」。
2. **禁令三的 `urllib.request` 改为整个 `urllib`。**
   原因：import-linter 不接受外部包的子模块。整包设禁更严。
   `urllib.request` 的文本形态另由 `deploy/scripts/check_egress.sh` 的 E2 静态扫描把关。
3. **禁令三加了 `allow_indirect_imports = True`。**
   原因：不加的话 `backend.llm.ollama → backend.core.http → httpx` 这条**正当**链路会被判违规——
   而「全仓库出网收口到 core.http 这一个受限工厂」正是本禁令想要的形态。加了之后只禁**直接** import，
   语义才对。**这条是必要修正，不是放宽**：护栏测试 `tests/guardrail/test_import_bans.py` 注入
   `import httpx` 到 `backend/report/` 后，禁令三确实拦下了。

另有两处 `# noqa` / `# nosec` 就地标注，均在 `backend/core/config.py`：
`APP_HOST="0.0.0.0"`（CLAUDE.md §9 的 uvicorn 命令本就要求绑全网卡）与
`PG_PASSWORD="fts"`（本机 initdb 用 trust 认证，真实口令走已 gitignore 的 `.env`）。

### 3.7 模型 digest 口径 = manifest 文件的 sha256

Ollama v0.6.8 的 `/api/show` **不返回 digest 字段**。改用 `OLLAMA_MODELS` 下该模型
manifest 文件的 sha256（与 `ollama list` 的 ID 列同源，前 12 位可肉眼比对）。
`healthcheck.sh`、`pull_models.sh`、`.env.example`、集成测试**四处口径一致**。

已经给你铺好的接口约定：

  摄取失败抛 `IngestionError`（FTS-1003）阻断，**绝不静默降级**（铁律 7）；
  源内值冲突抛 `DataConflictError`（FTS-2001，v6 已扩展口径以承载刘斌 C 类到期日冲突）。
- **契约**：`from backend.schemas import ...`，全部 `extra="forbid"`。
- **ORM 基类**：`from backend.models import Base`，`alembic revision --autogenerate` 立刻可用。
- **落库核对表**：`docs/M0_规格锁定.md` §4，8人/8机/12课目/6空域/2跑道逐格核对。
  **特别注意 AC73 是 JL-8 不是 JL-9；JL-9 只有 AC84/AC95 两架。**
- **`last_done_date` 原始 PDF 不提供，必须写 NULL**，由 S-12 处理为「从本周周一起算、不计欠账」。
  **写成 `gap=999` 会让基准周假性不可行**（CLAUDE.md §11 明列的反模式）。
- **§3.1.1 一致性断言要固化进管线**：学员在 A 类应为「单飞」、B/C/F 类应为「带飞」，
  成熟飞行员「单飞」，教员「教员」。不一致即抛 FTS-2001 阻断入库。
  这正是 2026-08-07 发现 `missions.pdf` 与 `personnel.pdf` 打架的那个检查。
- **PDF 抽取必须带修复层**（v6 §1.5 / §5.2）：文本流里课目编号被硬换行截断成 `mis` / `sionB-1`，
